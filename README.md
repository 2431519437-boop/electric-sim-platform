## 一、作品简介

### 1.1 痛点

电工电子实训长期受三个问题困扰：

| 痛点 | 具体表现 |
|---|---|
| **耗材成本高** | 面包板、元件、导线反复插拔损耗；元件烧毁是常态 |
| **指导无法规模化** | 一位教师面对 40 名学生，无法逐人检查"接线对不对" |
| **错误不可复现** | 短路烧元件只在一瞬间，学生说不清哪里错了，教师无法复盘 |

已有的电路仿真软件（Multisim / Proteus / LTspice）解决了**计算**问题，但没有解决**教学**问题：
它们不做接线判定，没有实验流程，不记录学生过程，也不能装在学生手机上。

### 1.2 我们的做法

把实训完整搬到 Web 与移动端，核心是三个自研模块：

1. 用 **3D 交互**还原面包板接线手感（拖拽、磁吸、拉线、橡皮筋跟随）
2. 用 **并查集 + 节点电压法**把"一堆孔位和导线"变成真实的电路计算
3. 用 **图同构匹配**自动判定学生接线是否与标准电路**电气等价**

第 3 点是本作品的核心 —— 它让"自动批改接线"从**不可能**变成**可量化**。

### 1.3 目标用户

- **学生**：课前预习接线、课中自主实验、课后复盘错误
- **教师**：布置实验、查看全班接线与得分、定位共性错误

## 二、核心创新

### 创新点 1：并查集拓扑识别

面包板内部有多条横向铜条，同一铜条上的插孔电气互通。**"哪个孔和哪个孔是一回事"是整个仿真的地基**。

我们把三类元素纳入并查集：

```
hole:<板ID>:<孔ID>      面包板插孔
pin:<元件ID>:<引脚名>    元件引脚
导线两端                连接关系
```

并查集合并后，每个集合即一个**电气节点**。短路检测也随之自然得出：电源正负引脚落在同一集合即为短路。

**为什么用并查集**：铜条、引脚、导线叠加后形成的连通关系是典型的等价关系，并查集保证近线性复杂度，且天然支持"拖动元件后重新计算"。

> 实现：`src/circuit/unionFindTopo.js` → `buildElectricalNodes()`

### 创新点 2：改进节点电压法（MNA）求解

在拓扑结果上生成类 SPICE 网表并求解：

| 元件 | 建模方式 |
|---|---|
| 电阻 / 电位器 | 电导 G = 1/R 参与 stamping |
| 电压源 | 引入支路电流作为额外未知量（MNA 扩展） |
| 发光二极管 | 正向压降 Vf + 等效串联电阻 Rf |
| 开关 | 闭合 0.001Ω / 断开 1e9Ω |

求解使用带部分主元的高斯消元，输出全部节点电压与支路电流 —— 这是仪表读数与 LED 点亮判断的依据。

> 实现：`src/circuit/circuitCore.js` → `generateNetlist()` / `solveCircuit()`

### 创新点 3：图同构接线等价判定 ★

#### 问题：为什么不能"逐根导线比对"

学生插的孔位、走线长度、导线根数千差万别，但**电气结构可能完全相同**：

- R1 与 R2 **互换位置**，测得的 U(R₂) 与 I 完全一致 → 必须判对
- 从板子左端还是右端接线、导线绕几圈 → 与正确性无关
- 真正该判的是「**电气结构是否等价**」，不是「线是不是这么拉的」

#### 方案：带标签多重图的子图同构

把电路抽象成图：

| 图的元素 | 对应物理对象 | 标签 |
|---|---|---|
| 顶点 | 一个电气节点（并查集输出） | 无 |
| 边 | 一个元件 | 类型 + 参数；电源、LED 带方向 |

用 VF2 思路的回溯搜索求**顶点双射**：

1. **度数序列剪枝** —— 两边顶点度数排序后必须逐个相等，否则立即失败
2. **按度数降序映射** —— 先约束最强的顶点，减少回溯
3. **每对已映射顶点间**，边的类型、数量、方向必须一致
4. 全部映射成功即「拓扑等价」

匹配成功后，再把学生图上的元件参数与标准答案比对，区分「结构错」还是「参数错」。

#### 为什么用 VF2 回溯，而不是 Weisfeiler-Lehman

这也是答辩时最容易被追问的一点，所以先在方法上说明白：

**WL（颜色细化）只能给出同构的必要条件，不能判定同构。** 两个 WL 签名完全相同的图，仍可能不同构。

经典反例：**C6（六边形）与 2C3（两个三角形）** —— 都是 2-正则图、6 个顶点、6 条边，
1-WL 迭代后所有顶点都落在同一颜色类，签名逐位相同，但二者显然不同构（一个连通、一个不连通）。

也就是说：**用 WL 判分，会把接错的电路判成对的。**

本项目用的是「度数序列剪枝 + 回溯 + 顶点双射校验」，在课设规模（3~8 个顶点）是**精确判定**，
且标签（元件类型 / 参数 / 方向）全程参与匹配。

这个反例已经固化为测试（`scripts/tests/isomorphism.test.mjs`）：

```
✓ 1-WL 给 C6 与 2C3 的签名完全相同     ← WL 在这里会误判
✓ C6 与 2C3 判为不匹配                  ← VF2 正确区分
✓ C6 与改名后的 C6 判为同构（编号无关）
✓ 边上类型标签不同 → 判为不匹配
✓ 有向边反向 → 有向判定下不匹配，放开方向后可匹配
```

同理，**不能把"引脚顺序"当标签**：电阻、电位器两端对称，反接在电气上完全等价；
只有电源、LED、二极管这类有方向元件才比较方向。把引脚序当标签会造成大量误判为错。

#### 判定结论一览

| 结论 | 判定依据 | 学生看到的提示（串联实验） |
|---|---|---|
| ✅ 通过 | 与标准答案图同构 | 接线与标准串联回路完全等价 |
| ✅ 通过（换位） | 匹配到"R1/R2 互换"变体 | 顺序与图纸相反，但电气完全等效 |
| ❌ 未检测到电源 | 图中无 VSRC | 未检测到电源，请先放置恒压源 |
| ❌ 缺元件 | 缺少必需类型 | 回路中缺少可变电阻 |
| ❌ 未闭合 | 边数不足 / 存在度数为 1 的悬空端 | 回路未闭合：还缺 1 处连接 |
| ❌ 多接 | 存在标准答案没有的元件类型 | 回路中多接了元件：发光二极管 |
| ❌ 参数错 | 结构匹配但参数超容差 | R1 阻值应为 200Ω，当前为 87Ω |
| ❌ 极性反 | 放开方向后能匹配 | 电源极性接反（V+ 与 V− 对调） |
| ❌ 结构错 | 以上均不成立（如串联接成并联） | 接线结构不符合标准串联回路 |

全部文案可由实验配置的 `grading.messages` 覆盖；未覆盖的沿用 `DEFAULT_MESSAGES` 通用文案，
因此新增实验时既能自定义措辞，也不会漏掉任何一种结论。

> 实现：`src/circuit/graphMatch.js` → `evaluateWiring()`

#### 一个必须说明的取舍

验证中发现：**电源极性接反在前两个实验中会被判通过，在 LED 实验中会被判错**。

这不是"时灵时不灵"，而是**标准答案里有没有方向性约束**决定的：

| 实验 | 接反后的判定 | 原因 |
|---|---|---|
| 串联分压 | ✅ 通过 | 接反与「R1/R2 换位」的标准答案同构；串联回路互换电阻位置，电压电流幅值完全相同 |
| 并联分流 | ✅ 通过 | 并联只有两个电气节点，接反 = 交换节点标号，是同一张图的自同构 |
| LED 限流 | ❌ 报极性反 | 标准答案含方向性元件 LED，接反后无法被任何对称性吸收 |

按平台既定原则「电气等价即通过」，前两个实验判通过是自洽的；
而 LED 实验里接反会真实导致不导通，必须判错。

若要前两个实验也严格要求正接，正确做法是把 LED 纳入标准答案，
或把仪表极性单独检查，而不是在图同构里加特例。

### 创新点 4：分级判分模型

「对 / 错」二元判分在教学场景里过于粗暴 —— 会误伤两类学生：

- 用了**等效替代**（例如手头没有 200Ω，用两个 100Ω 串联），电学上完全正确，却因结构不同被判错
- 多接了一个不影响核心回路的元件，核心接线其实是对的

于是把结论分成五档，每档给不同分数系数（系数可由实验配置覆盖）：

| 档位 | 判定依据 | 默认系数 |
|---|---|---|
| `exact` 接线正确 | 与标准答案图同构（含 R1/R2 换位） | 1.0 |
| `valueOnly` 结构正确·参数不符 | 拓扑能匹配，但元件参数超容差 | 0.8 |
| `equivalent` 等效电路 | 结构不同，但**实测电压/电流与理论一致**（默认 5% 容差） | 0.75 |
| `partial` 部分正确 | 核心回路正确，只是多接了非必需元件（子图同构） | 0.5 |
| `wrong` 接线错误 | 缺件 / 未闭合 / 极性反 / 结构错 / 短路 | 0.2 |

两个实现要点：

**① 等效判定比的是"行为"，不是"结构"。**
拿学生电路的**真实求解结果**（仪表读数）与理论值比对。理论值必须按**标准答案的元件参数**计算，
而不是学生实际放的元件 —— 否则"两个 100Ω 串联当 200Ω"这种等效永远算不对。

**② 阶位不能绕过硬错误。**
极性接反、缺件、未闭合这类错误一律落 `wrong`，拿不到等效分。
（已有测试固定：LED 接反虽然读数接近 0、看似"无害"，仍判 `wrong`。）

最终分 = `扣分后的原始分 × 档位系数`，报告里会明确写出折算过程，
例如「原始 100 分 × 系数 0.75 = 75 分」，并说明为什么给这一档。

> 实现：`src/circuit/tieredGrade.js`（纯函数，前后端共用）
> 测试：`scripts/tests/tiered-grade.test.mjs`（39 项，含真实求解器验算）

## 三、系统架构

### 3.1 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 前端框架 | Vue 3（`<script setup>`） | 响应式状态与组件化 |
| 3D 渲染 | Three.js 0.160 | 程序化几何，零外部模型依赖 |
| 构建 | Vite 5 | 秒级构建 |
| 后端 | Node 24 + `node:sqlite` | **零第三方运行时依赖** |
| 移动端 | Capacitor 7 | Web 代码直接打包 Android |
| 多端扩展 | 微信小程序 | 复用同一后端 |

### 3.2 分层

```
┌─────────────────────────────────────────────┐
│  表现层  App.vue / LabFlow / ThreeScene …    │
├─────────────────────────────────────────────┤
│  交互层  sceneEngine.js（3D 场景与拾取）      │
├─────────────────────────────────────────────┤
│  算法层  unionFindTopo / circuitCore /       │  ← 前后端共用同一份
│          graphMatch / readings               │
├─────────────────────────────────────────────┤
│  配置层  src/experiments/*.js（实验定义）     │
├─────────────────────────────────────────────┤
│  服务层  server/（鉴权、记录、报告、分析）     │
└─────────────────────────────────────────────┘
```

**关键设计**：算法层不依赖 Three.js 与 DOM，因此**前端本地计算与后端计算是同一份源码**，
不是两套实现 —— 这从根上消除了"本地算对、后端算错"的风险。

### 3.3 实验配置化（本作品最值得说的一项工程能力）

最初整个项目只能做**一个**实验：元件、公式、表格列、判分标准全部硬编码在 `App.vue` 里。
现在把这些全部抽成一份配置（`src/experiments/*.js`）：

| 配置项 | 决定什么 |
|---|---|
| `scene.components` | 预置哪些元件、摆在哪 |
| `roles` | 电源 / 固定电阻 / 可变电阻 / LED 分别是哪类元件 |
| `power` | 电源要求调到的电压与容差 |
| `measurements` | 电压表测谁两端、电流表串谁支路、仪表说明文字 |
| `formulas` | 理论值怎么算 |
| `dataPoints.columns` | 数据表有哪些列 |
| `dataPoints.read` | 一行数据从当前读数怎么生成 |
| `theory.rows` | 理论参考面板显示什么公式 |
| `scoring` | 基础分、提示扣分、错误扣分、及格线 |
| `grading` | 标准答案图、必需元件、提示文案 |
| `hints` | 「使用提示」按钮说什么 |
| `steps` / `content` | 实验环节、教学弹窗、进入场景时的连线提示 |

**结果：新增一个实验 = 新增一份配置 + 注册表加一行，前后端代码都不用改。**

这一点已被两次验证：

1. **并联分流实验**：新增实验时 `server/` 与 `src/circuit/` 未作任何改动。
2. **LED 限流实验**：元件组合不同（没有固定电阻）、标准答案含方向性元件，
   判分、求解、读数、数据表全部由配置驱动，同样未改引擎代码。

LED 实验还顺带照出了三处残留的写死文案 —— 进入场景的连线提示、仪表说明文字、
电源电压要求，现在都已收进配置（`content.schematic.flashTip`、`measurements.labels`、`power`）。

| 实验 | 元件组合 | 变量 | 核心结论 |
|---|---|---|---|
| 串联电路分压规律 | 电源 + R1(200Ω) + 电位器 R2 | R2 阻值 | U₂ = U·R2/(R1+R2) |
| 并联电路分流规律 | 电源 + R1(200Ω) + 电位器 R2（并联） | R2 阻值 | I₂ = U/R2，支路电流独立 |
| LED 限流电阻的选择 | 电源 + 电位器 R2 + **LED** | R2 阻值 | I = (U − U_F)/(R + R_F) |

三者均由同一套引擎驱动，差异全部体现在各自的配置文件里。

## 七、运行与部署

### 7.1 本地开发

```bash
npm install
```

```bash
PORT=8080 node server/index.js    # 由后端托管静态文件 + 提供 API
```

首个注册的账号自动成为教师；支持账号体系、记录落库、报告提交、教师端统计。

### 7.3 Android 打包

```bash
npm run build
npx cap sync android
cd android && ./gradlew assembleDebug
```

产物：`android/app/build/outputs/apk/debug/app-debug.apk`
**升级时必须递增 `versionCode`**，否则无法覆盖安装。

预编译安装包与部署文档见 `发布/` 目录。

### 7.4 生产部署

`deploy/` 目录提供 Dockerfile、Caddy 配置、健康检查与自动回滚脚本。

### 7.5 纯静态演示站（GitHub Pages）

给评审/老师一个**点开就能用**的网址，不需要装任何东西、也不需要后端。

**为什么能纯静态跑**

本作品的核心功能（3D 交互、并集拓扑识别、MNA 求解、图同构判分、分级判分、数据记录）全部在浏览器本地完成。
没有后端时 `detectBackend()` 探测 `/api/health` 失败，前端自动回退到本地模式，
记录写入 localStorage——功能完整，只是没有账号体系与教师端。

**构建与本地预演**

```bash
npm run build
npm run preview:static      # http://127.0.0.1:5200/esim/
```

`preview:static` 会**模拟 GitHub Pages 的项目站点形态**：把 `dist/` 挂在 `/esim/` 子路径下，
并且和 Pages 一样对未知路径直接返回 404（不做 SPA 回退）。
之所以要这样预演，是因为部署到 `https://<用户>.github.io/<仓库>/` 时所有资源都在子路径下，
前缀写错会白屏，而本地 `vite preview` 是根路径，测不出这个问题。

> `vite.config.js` 里 `base: './'` 用的是相对路径，所以站点放在任意子路径下都能用，
> 不需要把仓库名写进配置。

**自动发布**

仓库里已带 `.github/workflows/deploy-pages.yml`：

1. 在 GitHub 仓库页 `Settings → Pages → Source` 选 **GitHub Actions**
2. push 到 `main` 即自动构建并发布
3. 访问 `https://<用户名>.github.io/<仓库名>/`

> 免费账号的 GitHub Pages 要求仓库为 **public**。若不想公开源码，
> 可以只把 `dist/` 的内容推到另一个公开仓库（源码留在私有库）。

**产物**

`发布/电工电子实训-Web静态站.zip`（约 200 KB）内含 `index.html`、`assets/`、`.nojekyll`，
解压到任意静态托管（校园服务器、Nginx、对象存储）即可访问，无需任何后端。

## 十、已知限制与后续规划

### 10.1 已知限制（如实说明）

| 限制 | 影响 | 规划 |
|---|---|---|
| 仅支持**直流稳态** | 无法做 RC 充放电、交流相量 | 扩展瞬态（后向欧拉）与相量分析 |
| 器件模型较简化 | LED 用 Vf + Rf 近似，精度不及专业工具 | 明确教学定位，不追求工程级精度 |
| 实验数量为 **3 个** | 覆盖面仍偏窄 | 配置化后每个约半天：基尔霍夫定律验证、功率测量、RC 充放电 |
| 前两个实验不单独报极性错 | 电源接反被拓扑对称性吸收 | LED 实验已能检出；如需严格判定，标准答案纳入方向性元件即可 |
| 小程序端为**雏形** | 仅登录 + 串联实验 | 补完或明确标注为多端可行性验证 |
| LED 实验不允许加装固定电阻 | 学生若多放一个 R1 会被判"多接元件" | 若要允许，需要给标准答案增加"可选元件"概念 |

### 10.2 后续规划

1. 补 2~3 个实验，验证配置化抽象对**不同拓扑**的适应性
2. 求解器与 ngspice 交叉验证，输出精度报告（补上"精度"这一维度）
3. 小规模教学试用，收集前后测数据
4. 补充瞬态分析能力
